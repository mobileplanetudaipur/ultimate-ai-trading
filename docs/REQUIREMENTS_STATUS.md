# Requirements Status

This status map describes the repository as it exists in this worktree. “Implemented” refers to local paper-simulation behavior, not production or broker verification.

| Area | Status | Evidence |
|---|---|---|
| Platform | React 19 / TypeScript single-page app built with Vite and Tailwind, wrapped in a Tauri 2 shell; no backend service or database | `package.json`, `vite.config.ts`, `src-tauri/` |
| Native packages | A self-contained Windows NSIS candidate is built from this worktree and passed an isolated install/startup/uninstall smoke test. It is unsigned; no signed public release. macOS, Android, and iOS/iPadOS packages are not built. | `docs/BUILD_PROVENANCE.md`, `docs/releases/README.md` |
| Native broker access | Tauri supervises the bundled connector. The connector reports verified read-only account data and exposes a narrow, explicitly gated manual demo-order flow. No terminal/account password is handled by the app. | `src-tauri/src/lib.rs`, `local-adapter/bridge.py`, `local-adapter/order_execution.py` |
| Automatic Windows XM MT5 connection | Implemented read-only: Tauri starts a bundled connector automatically; it attaches to an existing terminal, verifies XM demo/live account identity, returns actual status/symbol data, and stops with app exit. The installed flow needs no separate Python, PowerShell, token, or bridge startup. Broker sign-in remains in official MT5. Reconnect and update matrix remain unverified; browser manual setup remains read-only. | `src-tauri/src/lib.rs`, `src-tauri/tauri.windows.conf.json`, `local-adapter/bridge.py`, `scripts/smoke-windows-installer.ps1` |
| Strategy automation | Not connected to broker execution. Strategy run controls continue to govern paper proposals only; no strategy can submit an XM order. | `src/services/strategyEngine.ts`, `src/services/persistentRunControl.ts`, `src/components/XMOrderTicket.tsx` |
| Manual demo order ticket | Implemented for the Windows app only: session phrase gate, account/mode binding, broker preflight, expiring one-use review confirmation, per-order submit confirmation, stop/target and risk checks, broker-result display, and an account-keyed durable ledger. No XM terminal or broker order has been used to verify runtime behavior. | `src/components/XMOrderTicket.tsx`, `src-tauri/src/lib.rs`, `local-adapter/bridge.py`, `local-adapter/order_execution.py` |
| Live order execution | Hard-locked in the connector and executor by a false release-approval flag. A live login remains read-only; live order preflight/submission are not available. | `local-adapter/order_execution.py`, `local-adapter/bridge.py`, `src/components/XMOrderTicket.tsx` |
| Market data | Browser and paper simulation use synthetic quotes/candles. Windows app can display exact XM quotes and M15 history from the signed-in demo/live terminal; live order submission remains locked. Market session/event context and paper account/risk values remain simulated. | `src/services/xmMarketData.ts`, `src/services/marketDataService.ts`, `local-adapter/bridge.py` |
| Broker observation | Read-only XM MT5 account, symbol, quote, candle, and reconciliation snapshots. No write path. Current candidate was not connected to MT5 during this continuation. | `local-adapter/bridge.py`, `src/services/xmMarketData.ts`, `src/views/ConnectionsSettingsView.tsx` |
| Broker quote readiness | Runtime-gated on fresh valid ticks and at least 50 valid M15 bars per instrument; stale/unavailable feeds are marked unusable. No live tick/strategy-execution verification has been performed in this worktree. | `local-adapter/bridge.py`, `src/services/xmMarketData.ts` |
| Contract terms | Adapter displays terminal-provided symbol metadata; local sizing assumptions remain unverified for broker execution | `local-adapter/bridge.py`, `src/services/brokerGateway.ts`, `src/views/ConnectionsSettingsView.tsx` |
| Operating modes | Local paper simulation remains separate. Manual demo orders require explicit session activation and individual order confirmation. A live login cannot arm the route. Strategy automation remains disconnected from the broker. | `src/App.tsx`, `src/services/riskEngine.ts`, `src/views/ConnectionsSettingsView.tsx`, `local-adapter/bridge.py` |
| Risk controls | Local paper checks include daily entry limits with UTC rollover, a cumulative session drawdown baseline, pending-entry reservations, supported-symbol checks, size caps, data validation, synthetic event windows, and a conservative UTC market-hours lock. These are not broker-enforced controls. | `src/services/riskEngine.ts`, `src/tests/runTests.ts` |
| Recovery | Paper checkpoints remain browser-local. Broker writes are persisted to a SQLite ledger before send; `UNKNOWN` or interrupted `SUBMITTING` outcomes block more orders. Automatic broker reconciliation/resolution is not implemented; XM restart-recovery behavior is unverified. | `local-adapter/order_execution.py`, `local-adapter/bridge.py`, `src/services/storageCheckpoint.ts` |
| Research metrics | Paper-only; no validated backtests, out-of-sample results, or annualized Sharpe calculation | `src/services/metricsCalculator.ts`, `src/components/ExecutionQualityModal.tsx` |
| Reconciliation | Read-only XM demo/live account, open positions/orders and 30-day history/deals are available; incomplete snapshots fail closed. This is not yet an automatic reconciliation/resolution mechanism for app-created broker orders. | `local-adapter/bridge.py`, `src/services/xmMarketData.ts`, `src/views/ConnectionsSettingsView.tsx` |
| Development exposure | Vite dev/preview and optional MT5 adapter bind to loopback; adapter requires an in-memory local bearer token | `package.json`, `vite.config.ts`, `local-adapter/bridge.py` |

Mock order tests and a no-terminal packaged-connector smoke check do not establish XM demo fills or production broker behavior. No MT5 connection or broker order was used during these checks. No changes were committed, pushed, or deployed.
